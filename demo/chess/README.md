# Ornate · 3D Chess Salon

Кинематографичные онлайн-шахматы: скульптурные фигуры, стол из тёмного камня и латуни, живой список столов и партия на двоих через StarkFlow.

- **Живая версия:** https://ewenloy.github.io/starkflow/
- **Сервер:** `wss://starkflow.orkestr.run/ws`

Витрина показывает именно этот адрес в подписи лобби. Рабочий узел владельца в репозитории не лежит: он подставляется на сборке из переменной `STARKFLOW_WS_URL` (для Pages — переменная или секрет репозитория), а локально — из git-ignored `demo/chess/.env`; `scripts/build.mjs` перезаписывает в `dist/src/env.js`. Честная граница: в опубликованном бандле адрес всё равно виден любому, кто откроет сайт и заглянет в `src/env.js` — спрятать его от посетителя Pages нельзя, только из репозитория.

- **App ID:** `starkflow-chess`
- **Лобби:** `salon`
- **Язык:** английский по умолчанию, переключатель **RU/EN** в верхней панели; выбор запоминается в `localStorage`.
- **Движок:** Three.js + chess.js + нативный ES-модульный клиент StarkFlow (без сборщика и без бэкенда).

## Что внутри

| Слой | Что делает |
|---|---|
| `src/scene.js` | 3D-сцена: мраморная доска, латунная инкрустация, колонны, бра, пыль, bloom, тени, свободная орбитальная камера и анимации ходов: взятия с искрами и осколками, превращение со световым столбом, приземление с волной и фейерверк при победе. Доска и подписи полей слиты в несколько мешей, клетки и латунь больше не рисуются по одной. |
| `src/pieces.js` | Процедурные фигуры из сглаженных lathe-профилей: пешка, ладья, слон, конь, ферзь, король. У каждой фигуры свой силуэт (шар, зубцы, митра, лошадиная голова, корона, крест), части сливаются в 1–2 меша на материал, под каждой — контактная тень. Материалы — процедурный мрамор и оникс с прожилками, плюс золотая отделка: у каждой фигуры свой рисунок из тонких колец и наконечников, читаемый сверху. |
| `src/session.js` | Авторитетная для клиента модель партии: FEN, история SAN, очередь хода, шах/мат, пат, ничья, сдача, реванш. |
| `src/net.js` | Мини-клиент StarkFlow: `hello`, токен, комнаты, `room.list`, общее состояние `game`, события, ping, авто-переподключение. |
| `src/main.js` | Лобби, список комнат, HUD, карточки игроков, список ходов, модальные окна, подсказки, звук. Здесь же бейдж «что это за фигура» и подписи фигур. |
| `src/engine.js` | Шахматный движок: собственное представление доски, альфа-бета с таблицей перестановок, quiescence, дебютная книга и три уровня бота: Novice, Club player, Maestro. |
| `src/offline.js` | Локальная замена StarkFlow-клиента: оффлайн-партия идёт через тот же `ChessSession`, без сети. |
| `src/bot-worker.js` | Web Worker для расчёта хода бота, чтобы интерфейс не замирал. |
| `scripts/test-engine.mjs` | Проверки бота: мат в один, взятие висящей фигуры и 40 легальных полуходов на каждом уровне. |
| `scripts/test-resume.mjs` | Проверки возврата за стол: обрыв дольше серверного таймаута, перезагрузка вкладки и закрытый стол — партия продолжается, а не превращается в зрительский вид. |
| `vendor/` | Точные версии Three.js, chess.js и шрифтов, чтобы страница работала статически. |

## Как играть

1. Откройте [страницу](https://ewenloy.github.io/starkflow/) и введите имя.
2. Создайте стол или выберите существующий.
3. Скопируйте ссылку на стол и отправьте другу.
4. Первый игрок — белые, второй — чёрные. Остальные попадают в зрители.
5. Нажмите на фигуру, затем на подсвеченное поле. Камера крутится мышью или пальцем прямо по доске, колесо/пинч — зум, нижняя панель держит четыре действия: **Перевернуть**, **Подсказка**, **Фигуры** (подписи) и **Вид сверху** (или клавиша **T**). На телефоне пятая кнопка открывает лист с ходами, часами, ничьей и сдачей.

> Игровая сессия хранится в `sessionStorage` отдельно для каждой вкладки. Если браузер всё же скопировал сессию при открытии второй вкладки, используйте приватное окно или другой профиль.

### Оффлайн с ботом

Кнопка **Play vs bot** в лобби запускает игру без сервера:

- **Novice** — считает на два хода, часто ошибается;
- **Club player** — итеративное углубление с quiescence-поиском и небольшим разбросом оценок;
- **Maestro** — тот же поиск с бюджетом до 1.8 с, таблицей перестановок, нулевым ходом и killers/history: находит маты, видит тактику и не зевает висящие фигуры.

Книга дебютов (e4, d4, Nf3, c4 и популярные ответы) держит начало партии в человеческом русле, а расчёт идёт в Web Worker — интерфейс не замирает.

Можно выбрать белых, чёрных или случайную сторону. После партии доступен реванш с переменой цвета.

## Локальный запуск

Никаких зависимостей и сборки не нужно:

```bash
cd demo/chess
npm run dev        # http://127.0.0.1:5173
```

Или любой статический сервер из этой папки, например `python -m http.server 5173`.

## Сборка для Pages

```bash
cd demo/chess
npm run build      # складывает статику в dist/
```

`dist/` — самодостаточная папка: `index.html`, `src/`, `vendor/`, `favicon.svg`. Именно её публикует workflow `.github/workflows/pages.yml`.

## Сетевая модель

Вся партия лежит в одном ключе общего состояния комнаты (`game`) как JSON:

```json
{
  "v": 1,
  "rev": 7,
  "fen": "r1bqkbnr/pppp1ppp/2n5/4p3/2B1P3/5N2/PPPP1PPP/RNBQK2R w KQkq - 4 4",
  "moves": ["e4", "e5", "Nf3", "Nc6", "Bc4"],
  "whiteId": 1,
  "blackId": 2,
  "status": "playing",
  "lastMove": { "from": "f1", "to": "c4", "san": "Bc4", "color": "w" }
}
```

- Любой клиент может записать `game`; сервер упорядочивает записи и рассылает `state.changed` всем, включая автора.
- Ходы проверяются на клиенте через chess.js; `rev` защищает от применения устаревшего состояния.
- Хост (самый старый активный игрок) создаёт начальное состояние и сажает второго гостя за чёрных.
- При выходе игрока партия завершается по «оставленному столу»; обрыв связи партию не завершает: сервер держит место 30 секунд, клиент переподключается сам и возвращается за стол.
- Места лежат в `game` дважды: `whiteId`/`blackId` — место в комнате, `whiteUserId`/`blackUserId` — личность игрока. Если комната уже отпустила отключившегося и он вернулся с новым `playerId`, хост возвращает ему место по `userId`, так что партия продолжается с того же хода, а не превращается в зрительский вид.
- Перезагрузка вкладки — тоже возврат за стол: `room.leave` при закрытии страницы не отправляется, а вход по ссылке с `?room=<id>` и сохранённым в `sessionStorage` токеном возобновляет прежнее место.
- Одинаковые имена столов разрешены, вход идёт по `roomId`.
- Место потерявшего связь держится дольше, чем обещает интерфейс: комната просит у сервера `suspendTTL: 300`, а второй игрок видит над доской полосу «Соперник вышел — ждём 30 с» с кнопками «Подождать ещё 30 с» и «Завершить партию». Поэтому стол не исчезает, пока вы ждёте, и партия не зависает навсегда, если соперник так и не вернулся.
- Перезагрузка вкладки не втягивает в партию молча: незавершённый стол запоминается в `sessionStorage`, и после загрузки приложение спрашивает «Продолжить / Новый стол». Если стол уже закрыт, оно честно пишет об этом и предлагает новый.

## Мобильные устройства и производительность

Сцена — самый тяжёлый кусок демо, поэтому качество выбирается один раз при старте, а не подбирается на каждом кадре:

- `qualityProfile()` в `scene.js` смотрит на `pointer: coarse`, размер окна, `hardwareConcurrency`, `deviceMemory` и `devicePixelRatio`: на телефоне — DPR 1.25 (без MSAA и блума), теневая карта 1024, меньше пыли и частиц; на десктопе — DPR до 1.75, 2048 и пост-обработка. `#adaptQuality()` дополнительно снижает DPR, если кадры стабильно медленные, и возвращает обратно, когда запас вернулся.
- **Фигуры больше не рисуются по частям.** Раньше стартовая позиция стоила 344 меша и ~209 тысяч треугольников (у коня было 20 мешей, у ферзя 24). Сейчас каждая фигура сливается в 1–2 меша по материалу плюс контактная тень: 48 мешей на всю доску, ~83 тысячи треугольников. Предпросмотр фигуры (клик по ней) и подсветка работают в мировых координатах и от слияния не зависят.
- **Доска тоже.** 64 клетки слиты в два меша, латунная окантовка и уголки — в два, а 32 подписи полей собраны в один атлас: это минус 95 вызовов отрисовки и минус 32 текстуры 128².
- **Свет и материалы.** Свет сбалансирован под читаемость: тёплый ключевой, холодный контровой сзади-сбоку и мягкая подсветка зала дают графитовым фигурам контур, а слоновая кость перестала сливаться со светлыми полями. Тёмные поля чуть светлее, светлые чуть глубже — это разводит фигуры и доску по тону.
- Эффекты (`#burstAsset`, `#makeRipple`, `#makeFlare`, `#makeShard`, `#makeTrail`, `#makeGlow`) пулируются, геометрия и материалы кешируются по цвету. Подсветка шаха и подсказка используют общие материалы из `#markerAssets()`, поэтому не пересобирают шейдеры на каждом ходе.
- Точечные источники света больше не добавляются в сцену: изменение их числа заставляет рендерер пересобирать программы **всех** материалов. Свет «взятия» и шаха теперь аддитивный спрайт.
- **Камера кадрируется по свободной части экрана.** `setHudInsets()` получает от приложения границы HUD, считает расстояние по реальным углам доски (итеративно, потому что наклонная доска проецируется шире, чем плоская) и сдвигает камеру вместе с целью вдоль её же вертикали: доска встаёт в промежуток между полосами HUD, перспектива при этом не меняется.
- Камера смотрит на стол под 52°, а не под 36°: дальние фигуры больше не перекрывают друг друга, и силуэт читается.
- HUD уважает `env(safe-area-inset-*)`, кнопки на `pointer: coarse` не меньше 44–46 px, размытие подложек отключено (живой canvas под `backdrop-filter` пересчитывается каждый кадр), для узких и низких экранов есть отдельные полосы сверху и снизу, а панель ходов на телефоне — выдвижной лист, который не закрывает доску в закрытом виде.
- В скрытой вкладке цикл рендера останавливается (`visibilitychange`), при возврате — продолжается без скачка времени.

## Подписи фигур и обучение

- **Тап по любой фигуре** (своей или соперника) показывает бейдж: глиф, название с цветом («Чёрный конь») и короткое правило хода. Вокруг фигуры на доске загорается кольцо.
- Кнопка **«Фигуры»** в нижней панели включает режим подписей: над каждой фигурой появляется её глиф. Режим запоминается в `localStorage` и выключается сам, когда игрок его больше не включает.
- Подсказки (`Hint`) по-прежнему бесплатны: это демо, а не витрина расходуемых товаров.

## Ограничения демо

- Нет турнирных часов и рейтинга.
- Нет серверной валидации шахматных ходов: это дружеский салон, а не античит-платформа.
- Подсказка — короткий поиск на ~0.5 с, не полноценный шахматный движок.
- Для двух игроков в одном браузере нужен отдельный профиль/приватное окно.
- Партия живёт в памяти комнаты: если стол закрылся (никого не было 5 минут) или сервер перезапустился, вернуть ходы нельзя — приложение честно вернёт в лобби и предложит новый стол.
