# Справочник ACE плагина StarkFlow

Все действия (Actions), условия (Conditions) и выражения (Expressions) плагина: параметры, что читать и когда.
Пошаговая сборка игры из этих кубиков — в [GAME-GUIDE.md](GAME-GUIDE.md), схема сообщений — в
[PROTOCOL.md](PROTOCOL.md).

Обозначения: **триггер** — срабатывает один раз в момент события, остальные условия можно ставить где угодно.
`Id` игрока — это число внутри комнаты (1, 2, 3…), оно меняется между сессиями; `UserId` — постоянный
идентификатор игрока, он живёт, пока сервер помнит токен.

## Свойства объекта StarkFlow

| Свойство | По умолчанию | Что делает |
|---|---|---|
| Server URL | `ws://localhost:8080/ws` | Адрес сервера. На https-странице (облачный предпросмотр C3, itch.io, GitHub Pages) нужен только `wss://` |
| App ID | `default` | Имя твоей игры на сервере. Комнаты с разными App ID не видят друг друга |
| Connection mode | Auto | Auto — режим выбирается по схеме адреса: `ws://` это игровой сервер, `http(s)://` это распределитель кластера. Single node — всегда подключаться напрямую, Cluster directory — всегда спрашивать ноду у распределителя |
| Log level | Info | Что плагин пишет в консоль браузера: Debug, Info, Warnings, Errors, Off |
| Auto reconnect | On | Сам переподключаться после обрыва и возвращаться в ту же комнату |
| Replay players on join | On | После входа выдать «On player joined» по каждому, кто уже в комнате (включая себя), чтобы один обработчик создал все объекты игроков |
| Send rate | Medium | Как часто уходит синхронизация объектов и свойств игроков. В игре меняется действиями Send rate |

Объект должен быть **Global** (или лежать на отдельном layout), иначе он создастся заново при смене layout и
соединение порвётся.

## Connection — подключение

### Условия

| Условие | Тип | Когда |
|---|---|---|
| On connected | триггер | Сервер принял соединение (в том числе после автоматического переподключения) |
| On disconnected | триггер | Соединение закрыто окончательно — попытки переподключения кончились или вызван `Disconnect` |
| On reconnecting | триггер | Плагин запланировал очередную попытку (до 10 попыток, пауза 1 с и дальше ×2 до 8 с) |
| Is connected | обычное | Истина, пока есть соединение (`connected` или `in-room`) |

### Действия

| Действие | Параметры | Что делает |
|---|---|---|
| Connect | `url`, `token` | Открывает соединение. Пустой `url` — берётся из свойств. Пустой `token` — берётся сохранённый (localStorage) |
| Disconnect | — | Закрывает соединение и выходит из комнаты |
| Set auth token | `token` | Задать токен игрока до `Connect`. Нужно в worker-режиме C3, где `localStorage` недоступен |
| Set name | `name` | Имя игрока. Уходит на сервер в `hello`, другие игроки видят его в `PlayerName` |
| Set region | `region` | Только в кластере: зафиксировать регион (`eu`, `ru`, …) вместо автоматического выбора ближайшего. Пустая строка — снова выбирать ближайший (и замерить заново) |

### Выражения

| Выражение | Возвращает | Что это |
|---|---|---|
| `AuthToken` | строка | Текущий токен игрока (для сохранения в LocalStorage-плагин) |
| `MyUserId` | строка | Постоянный id игрока |
| `MyName` | строка | Свой ник. До входа — то, что задал `Set name`; после входа — имя, подтверждённое сервером |
| `Region` | строка | Только в кластере: регион, к которому подключился плагин. Вне кластера — пусто |
| `Ping` | число | Задержка в мс: плагин шлёт `ping` раз в секунду независимо от игры и считает по ответу `pong`. `0` — ответа ещё не было |
| `ServerTime` | число | Время сервера в мс (удобно для таймеров, синхронных у всех) |
| `StatusString` | строка | `disconnected`, `connecting`, `connected`, `in-room`, `reconnecting` |

### Кластер и регионы

Если Server URL начинается с `http(s)://`, плагин считает его **распределителем** (directory): спрашивает ноду
(`POST /assign`), получает подписанный билет и подключается уже к ноде. Режим можно задать и вручную свойством
**Connection mode**, если адрес говорит не то, что нужно.

Если у распределителя несколько регионов, плагин сначала берёт их список (`GET /regions`), замеряет задержку до
каждого (несколько HTTP-запросов к `/health`) и подключается к ближайшему — как «best region» в Photon.
Результат запоминается на 10 минут, поэтому замер не повторяется на каждом подключении и реконнекте. Регион текущего
подключения виден в выражении `Region`, зафиксировать регион вручную можно действием `Set region`. Все жители одной
комнаты всегда попадают на одну ноду, даже если она в чужом регионе. Подробности — `docs/CLUSTER.md`.

## Room — комнаты

### Условия

| Условие | Тип | Когда |
|---|---|---|
| On joined room | триггер | Вошли в комнату (в том числе при возврате после обрыва — смотри `Resumed`; в том числе когда сами её создали) |
| On created room | триггер | Комнату создал именно ты (`Create room` или «Join or create» без существующей комнаты). Срабатывает перед `On joined room` |
| On join room error | триггер | `Join room` не удался: нет комнаты (**300**), заполнена (**301**), неверный пароль (**307**). Читай `ErrorCode`/`ErrorMsg` |
| On create room error | триггер | `Create room` не удался: имя уже занято (**308**), лимит комнат сервера, плохое имя (**306**) |
| On left room | триггер | Вышли из комнаты (`Leave room`) |
| On room list received | триггер | Пришёл ответ на `Request rooms` |
| Is in room | обычное | Истина, пока ты в комнате |
| Is host | обычное | Истина, если ты хост комнаты (самый старый активный игрок) |

### Действия

| Действие | Параметры | Что делает |
|---|---|---|
| Create room | `room`, `max-players`, `empty-ttl`, `lobby` | Создать **новую** комнату с этим именем и войти в неё. Если комната с таким именем уже есть — ошибка **308** (`On create room error`), дубликата не появится. В отличие от «Join or create» никогда не входит в чужую комнату. `max-players` = 0 и `empty-ttl` = -1 — «по умолчанию сервера» |
| Join room | `room`, `password` | Войти в комнату по **id** (точнее всего) или по имени (тогда — самая старая комната с таким именем). `password` — для закрытой комнаты, пусто — для открытой. Неудача — `On join room error` |
| Join or create room | `room`, `max-players`, `empty-ttl` | Войти, если комната с таким именем есть, иначе создать её. `max-players` = 0 и `empty-ttl` = -1 означают «по умолчанию сервера» |
| Join random or create room | `room`, `max-players`, `empty-ttl`, `matching`, `lobby` | Быстрая игра: войти в любую комнату со свободным местом (полные и с паролем пропускаются), иначе создать `room` (`max-players`/`empty-ttl` — как выше). `matching`: `fillroom` — самая полная из свободных, `randommatching` — любая, `serialmatching` — первая в списке. `lobby` — метка лобби: матчмейкинг идёт только по комнатам этого лобби, и созданная комната получает её же; пусто — все комнаты приложения. Выбор делает клиент по списку комнат; если выбранную комнату заняли/закрыли — плагин сразу создаёт свою |
| Join room with password | `room`, `password` | То же, что `Join room`, но для комнаты с паролем |
| Join or create room with password | `room`, `password`, `max-players`, `empty-ttl` | Войти в комнату с этим паролем, а если её нет — создать её закрытой |
| Leave room | — | Выйти из комнаты (соединение остаётся) |
| Request rooms | — | Попросить список комнат приложения. Ответ — триггер `On room list received` |

### Выражения

| Выражение | Возвращает | Что это |
|---|---|---|
| `RoomName` | строка | Имя текущей комнаты |
| `RoomId` | строка | Id текущей комнаты (например `8f3a1c04`) |
| `MyId` | число | Твой id внутри комнаты |
| `HostId` | число | Id игрока-хоста |
| `Resumed` | 1/0 | 1, если последний вход был возвратом в комнату, где ты уже был |
| `RoomCount` | число | Сколько комнат в последнем списке |
| `RoomPlayerCount` | число | Сколько игроков в комнате, в которой ты сейчас |
| `RoomMaxPlayers` | число | Лимит игроков комнаты, в которой ты сейчас: сколько максимум может войти |
| `RoomFree` | число | Сколько ещё игроков может войти в текущую комнату (0 — мест нет) |
| `RoomCreated` | 1/0 | 1, если текущую комнату создал ты |
| `RoomNameAt(i)` | строка | Имя комнаты с индексом `i` (с нуля) |
| `RoomIdAt(i)` | строка | Id комнаты с индексом `i` — его передавай в `Join room` |
| `RoomPlayersAt(i)` | число | Сколько игроков в комнате с индексом `i` |
| `RoomMaxAt(i)` | число | Лимит игроков в комнате с индексом `i` |
| `RoomFreeAt(i)` | число | Сколько мест свободно в комнате с индексом `i` (0 = мест нет) |
| `RoomIsFullAt(i)` | 1/0 | 1, если в комнате с индексом `i` нет свободных мест |
| `RoomLockedAt(i)` | 1/0 | 1, если для входа в комнату с индексом `i` нужен пароль |

Индексы только на чтение: если выйти за границы, выражения вернут `""` или `0`, ошибки не будет.

## Players — игроки в комнате

### Условия

| Условие | Тип | Когда |
|---|---|---|
| On player joined | триггер | Кто-то вошёл в комнату. Id нового игрока — в `LastPlayerId` |
| On player left | триггер | Игрок ушёл совсем. Id — в `LastPlayerId` |
| On player connection lost | триггер | У игрока пропала связь: он остаётся в комнате как `suspended` (по умолчанию 30 с, см. «Set player timeout»), id — в `LastPlayerId` |
| On player resumed | триггер | Игрок вернулся после обрыва. Id — в `LastPlayerId` |
| On host changed | триггер | Хост сменился (старый хост ушёл) |
| On player prop (key) changed | триггер | У кого-то изменилось свойство игрока. Id — в `LastPlayerId`, ключ — в параметре условия |

### Действия

| Действие | Параметры | Что делает |
|---|---|---|
| Set player prop | `key`, `value` | Записать своё свойство игрока (курсор, цвет, ready). Писать может только сам игрок, чужие значения подделать нельзя |
| Set player timeout | `seconds` | Сколько секунд сервер держит место за игроком с оборванной связью. `0` — удалять сразу: остальные получают «On player left» в момент обрыва, `suspended` не приходит. `-1` — вернуть серверное значение (по умолчанию 30 с). Действует на комнату, которую создаёт этот клиент, — вызывай до `Join room` / `Join or create room` |

### Выражения

| Выражение | Возвращает | Что это |
|---|---|---|
| `PlayerCount` | число | Сколько игроков в комнате (включая suspended) |
| `PlayerIdAt(i)` | число | Id игрока с индексом `i` (список отсортирован по id) |
| `PlayerNameAt(i)` | строка | Ник игрока с индексом `i` (тот же порядок, что у `PlayerIdAt`) |
| `PlayerName(id)` | строка | Ник игрока по его id. Свой — `PlayerName(MyId)`, в триггере — `PlayerName(LastPlayerId)` |
| `PlayerUserId(id)` | строка | Постоянный userId игрока |
| `PlayerStatus(id)` | строка | `active` или `suspended` |
| `PlayerProp(id, key)` | число/строка | Свойство игрока. Логические приходят как 1/0, отсутствующие — как 0 |
| `LastPlayerId` | число | Id игрока из последнего триггера про игроков |

## Events — быстрые сообщения

### Условия

| Условие | Тип | Когда |
|---|---|---|
| On event (code) | триггер | Пришло событие ровно с этим кодом |
| On any event | триггер | Пришло любое событие (удобно для логов) |

### Действия

| Действие | Параметры | Что делает |
|---|---|---|
| Send event | `code`, `data`, `to` | Отправить событие. `data` — строка: `str(x) & "," & str(y)` |

Значения `to`:

| Значение | Кому уйдёт |
|---|---|
| `""` (пусто) или `others` | всем, кроме тебя |
| `all` или `ALL` | всем, включая тебя |
| `"2"` (номер игрока) | только игроку с этим id |

### Выражения

| Выражение | Возвращает | Что это |
|---|---|---|
| `EventCode` | число | Код последнего события |
| `EventData` | строка | Данные последнего события |
| `EventFrom` | число | Id игрока, который прислал событие |

## Room state — общий стейт комнаты

Один набор ключей на комнату, значения видят все. Здесь живут общее HP босса, счёт, фаза игры.

### Условия

| Условие | Тип | Когда |
|---|---|---|
| On state (key) changed | триггер | Изменился конкретный ключ |
| On any state changed | триггер | Изменился любой ключ |

### Действия

| Действие | Параметры | Что делает |
|---|---|---|
| Set state | `key`, `value` | Записать значение (число, строка или bool) |
| Set state bool | `key`, `0/1` | То же, но явно логическое значение |
| Add to state | `key`, `delta` | Прибавить к числу. На сервере атомарно: одновременные удары не теряются |
| Toggle state | `key` | Переключить логическое значение |

### Выражения

| Выражение | Возвращает | Что это |
|---|---|---|
| `State(key)` | число/строка | Текущее значение ключа. Логическое — 1/0, отсутствующий ключ — 0 |
| `ChangedKey` | строка | Ключ из последнего изменения |
| `ChangedValue` | число/строка | Новое значение |
| `ChangedOld` | число/строка | Предыдущее значение |
| `ChangedBy` | число | Id игрока, который изменил |

Изменения приходят всем, включая автора изменения, — отдельно обновлять своё значение не нужно.

## Object sync — синхронизация объектов

Два уровня: **простой** (тег + автоматические объекты чужих игроков) и **низкоуровневый**
(владелец + слот), если нужен полный контроль. Обычной игре хватает простого.

Формат действия регистрации — один-в-один как в GamePush Channels: `Object`, `Tag`, `Scope`
(`Player state` / `Global state`), `Transform` (`None` / `Position` / `Position + angle` / `Full`),
`Interpolate transform`, `Layer`. Отличие только в том, что `full` у нас включает и `Z`, `mirror`,
анимацию и кадр.

### Синхронизация объектов

| Что есть | Тип | Смысл |
|---|---|---|
| Register object for sync `объект` as `тег` in `scope` state | действие | Что синхронизировать: тип объекта, тег, область, набор полей, сглаживание, слой. Вызови один раз одинаково на всех клиентах (например на `On start of layout`) |
| Register object variable for sync | действие | Добавить переменную инстанса (hp, ammo, счёт) в синхронизацию. Выбирается из списка — без опечаток, переживает переименование. Вызывать после `Register object for sync` и до `Start auto-sync` |
| Sync appearance | действие | Внешний вид объекта галочками: `blend` (режим смешивания), `color` (тинт RGB), `flipped` (вертикальный флип), `mirrored` (горизонтальный), `sampling` (сглаживание картинки), `opacity`, `visible`. Снятая галочка выключает только своё поле — остальные поля объекта (`Transform`) не трогаются |
| Sync animations | действие | Анимация спрайта галочками: `name` (имя анимации), `frame` (кадр), `speed` (скорость), `repeat-to` (последний кадр цикла). Для большинства игр хватает `name` + `speed`; `frame` — только для точной покадровой синхронизации, это лишний трафик |
| Bind local instance `объект` | действие | Выбранный инстанс — мой и уходит другим. Без этого действия `Start auto-sync` берёт инстанс, который лежит на слое |
| Start auto-sync | действие | Начать отправку своих объектов и создание/движение объектов остальных игроков |
| Stop auto-sync | действие | Остановить: чужие объекты удаляются, а свои плагин чистит на сервере |
| Is auto-sync active | условие | Истина после `Start auto-sync`, пока синхронизация идёт |
| For each object (tag) | условие-цикл | Обойти все синхронизированные объекты: мой и созданные для других. Пустой тег — все |
| On player proxy created (tag) | триггер | Плагин создал объект чужого игрока (`scope player`). Читай `ProxyUID`, `ProxyPlayerId`, `ProxyTag` |
| On player proxy destroyed (tag) | триггер | Объект чужого игрока исчез (игрок вышел или перестал слать). Срабатывает до удаления инстанса |
| On entity created (tag) | триггер | Появился общий объект (`scope global`), созданный хостом. Читай `EntityUID` и пикуй инстанс |
| On entity destroyed (tag) | триггер | Общий объект удалён. Инстанс уничтожается сразу после триггера |

`Transform`: `none` | `position` (X, Y) | `positionAngle` (X, Y, угол) | `full` (X, Y, Z, угол, размер,
отражение, анимация, кадр, видимость, прозрачность).
`Scope`: `player` — у каждого игрока свой объект; `global` — один объект, которым управляет хост
(в логах и в старых проектах он называется `host`, это одно и то же).

Объекты чужого игрока удаляются, как только его id пропадает из списка игроков комнаты — не только по
сообщению «вышел», поэтому фантом не остаётся даже после реконнекта, когда сообщение могло потеряться.
При обрыве связи сервер держит игрока в комнате как `suspended` 30 секунд (по умолчанию; `Set player timeout`
с `0` убирает игрока сразу, тогда его объекты удаляются в момент обрыва) и только потом шлёт «вышел» — пока он
в комнате, его объект на месте.

| Выражение | Тип | Смысл |
|---|---|---|
| `EntityUID` | число | UID текущего объекта: подставь в `System: Pick instance by unique ID` |
| `EntityTag` | строка | Тег текущего объекта |
| `EntityOwner` | число | Id игрока, который управляет объектом |
| `EntityType` | строка | Имя типа объекта |
| `EntitySlot` | число | Номер слота у владельца (техническое) |
| `EntityField(key)` | любой | Поле текущего объекта: `x`, `y`, `z`, `angle`, `width`, `height`, `size`, `mirror`, `animation`, `frame`, `visible`, `opacity`, `uid`, `tag`, `owner`, `slot`, `type` |
| `EntityCount(tag)` | число | Сколько объектов с этим тегом (пусто — все) |
| `LocalEntityUID(tag)` | число | UID моего объекта с этим тегом |
| `PlayerProxyUID(playerId, tag)` | число | UID объекта, созданного плагином для игрока `playerId` |
| `ProxyPlayerId`, `ProxyTag`, `ProxyUID` | число/строка/число | Значения текущего чужого объекта в триггерах `On player proxy`/`On entity created/destroyed` |

Как это работает: один тег — один объект на игрока. Владелец шлёт своё, остальные применяют чужое со
сглаживанием (`Interpolate transform` в `Register object for sync` или общий `Set smoothing`). Тег едет вместе с данными, поэтому
объект чужого игрока появляется сразу, как только приходят его координаты, и исчезает, когда владелец
перестаёт их слать. Данные каждого игрока пакуются в свойства `_sf0…_sf7` (8 чанков по ~4000 байт на текущем сервере,
~1000 байт на старом — размер плагин берёт из `welcome`), поэтому в комнате одновременно уживаются несколько сотен мелких объектов; анимация и кадр синхронизируются только у
спрайтов. Переменные, добавленные через `Register object variable for sync`, едут в тех же чанках и
применяются чужим объектам; с `interpolate` числа доезжают плавно.

Внешний вид и анимация — это два отдельных действия, как в GamePush Channels: `Sync appearance` и
`Sync animations` (см. таблицу выше). Каждое владеет своей группой полей: галочки `Sync appearance` меняют
только `blend`/`color`/`flipped`/`mirrored`/`sampling`/`opacity`/`visible`, галочки `Sync animations` — только
`name`/`frame`/`speed`/`repeat-to`. Поэтому их можно ставить поверх любого `Transform`, не боясь, что одно
действие снесёт поля другого, а снятая галочка выключает ровно одно поле и не трогает позицию. Поля,
которых у объекта нет (тинт или режим смешивания у не-спрайта, анимации у тайлмапа), выбрасываются
автоматически — на другом клиенте такой объект просто получит остальные поля.

```
System: On start of layout
    → StarkFlow: Register object for sync Player as "player" in Player state (transform: Position, interpolate: yes)
    → StarkFlow: Sync appearance of Player (blend: no, color: yes, flipped: yes, mirrored: yes, sampling: no, opacity: yes, visible: yes)
    → StarkFlow: Sync animations of Player (name: yes, frame: no, speed: yes, repeat-to: no)
    → StarkFlow: Start auto-sync
```

Одна частая ловушка, и именно она выглядит как «синк не работает»: если игровая логика каждый тик ставит
анимацию всем объектам типа (`WariRix: Is moving → Set animation "walk"`), она перебивает синхронизированную.
События выполняются **после** тика плагина и выбирают все инстансы типа, включая чужие копии, поэтому у копии
остаётся `stat`/`fall`, хотя данные доезжают. Признак: зеркальность и позиция работают, а анимация «залипла» —
зеркальность ты ставишь внутри `Pick ... LocalEntityUID("player")`, а анимацию всем подряд. Держи свою логику
анимаций внутри выбора своего объекта:

```
System: Pick WariRix by unique ID StarkFlow.LocalEntityUID("player")
    + WariRix (Platform): Is moving  → Set animation "walk"
    + WariRix (Platform): Is falling → Set animation "fall"
    + WariRix (Platform): Is jumping → Set animation "jump"
```

И отключи поведения у чужих копий — Platform тянет их вниз и подставляет свои условия
(`On player proxy created → WariRix: Set Platform enabled to Disabled`).

Плагин сам ловит эту ошибку: если анимацию копии переписал кто-то, кроме него, в консоль один раз уходит
предупреждение `the events change the animation of the players' copies ("player"): expected "walk", got "stat"` —
с готовым именем события, которое надо обернуть в `Pick`. Уровень лога на него не влияет: это не отладка,
а ошибка в проекте.

Так у чужих копий видно не только где персонаж, но и какой у него цвет команды, куда он смотрит и что
он делает — без ручных событий на каждый кадр анимации.

### Как ведёт себя галочка `frame`

Кадр — не то поле, которое надо переписывать каждый тик. Чужая копия играет анимацию сама, с той же
скоростью, а рисуется она на `Smoothing` мс в прошлом. Поэтому плагин ставит `frame` только в трёх случаях:

- анимация началась заново (первый раз или после смены имени) — копия стартует с кадра владельца;
- анимация стоит (`speed` = 0) — кадр это и есть вся поза;
- имя не синхронизировано, кадр — единственное, что вообще есть.

Дальше кадры копия считает своими силами. Иначе получалось вот что: свернул вкладку — рантайм
перестаёт тикать, снапшоты не уходят, в буфере остаётся один последний, и плагин каждый тик ставил
его кадр заново. Анимация «дёргалась» и выглядела как запуск с начала.

Из этого же следует: `frame` действительно нужен только для покадрового синка (файтинг, точный
хитбокс). Для обычного персонажа оставляй `name: yes, frame: no, speed: yes`.

Привязка («какой инстанс мой») восстанавливается сама: если инстанс удалили (смена layout, респавн) или он
создан уже после `Start auto-sync`, плагин раз в полсекунды перепроверяет привязки и берёт новый инстанс
того же типа. Если плагин не нашёл, что привязать, он пишет об этом в консоль — ищи в логе
`no instance of ... to bind as mine`.

### Низкоуровневая синхронизация

| Что есть | Тип | Смысл |
|---|---|---|
| Register sync object (advanced) | действие | Связать выбранные инстансы с парой «id игрока + слот». Больше 10 галочек — точный список полей |
| Unregister sync object | действие | Перестать синхронизировать выбранные инстансы |
| Set smoothing | действие | Сколько миллисекунд чужие объекты доезжают до новых значений (0 — рывком). На сервере с каналом `sync` — на сколько мс в прошлом рисуются чужие объекты (буфер интерполяции) |
| Set smoothing (auto) | действие | Сглаживание по частоте отправки: `1.4 × интервал`, но не меньше 70 и не больше 300 мс. На сервере с каналом `sync` — адаптивный буфер: `1.5 × интервал отправки владельца + 3 × измеренный джиттер` (плюс окно батчинга, только если сервер пропускает снимки через него: текущий шлёт `sync` сразу и сообщает `syncNow`), 40…400 мс. Джиттер — насколько неравномерно приходят снимки: задержка мгновенно растёт при всплеске сети и медленно опускается, когда сеть успокоилась. Это значение стоит по умолчанию |
| Set send rate (mode) | действие | Как часто слать: fast 58/с, medium 30/с, slow 15/с |
| Set send rate (custom) | действие | Своя частота, 1–60 (выше 58 обрезается) |
| `SendRate` | число | Текущая частота отправки |
| `Smoothing` | число | Задержка, с которой сейчас рисуются чужие объекты, в мс: буфер интерполяции на сервере с каналом `sync`, «сколько мс доезжают» на старом сервере |
| `BufferDelay` | число | То же, что `Smoothing`, но в стиле GamePush-диагностики: худшая (наибольшая) задержка буфера среди игроков |
| `BufferSize` | число | Сколько снимков лежит в буфере (самый пустой из буферов). `0` — интерполировать не из чего |
| `Jitter` | число | Измеренная неравномерность прихода снимков в мс (у худшего игрока). Ровная сеть, даже с большим пингом, даёт маленькое число |
| `SyncedObjectCount` | число | Сколько объектов зарегистрировано |

Низкоуровневый уровень — это то, что делает `Register object for sync` внутри: `owner` = id игрока, `slot` — номер
объекта у этого игрока (у всех клиентов одинаковый), при совпадении с `MyId` объект отправляется,
иначе им управляет чужой игрок. Для перебора и чтения полей используй `For each object` и `EntityField`,
они работают и с этими записями (у них пустой тег).

## Errors — ошибки от сервера

| Что есть | Тип | Смысл |
|---|---|---|
| On error | триггер | Сервер прислал `err`. Читай `ErrorCode` и `ErrorMsg`. Поднимается всегда, вместе с `On join room error` / `On create room error` |
| On join room error | триггер | То же, но только когда неудачно закончился `Join room` |
| On create room error | триггер | То же, но только когда неудачно закончился `Create room` |
| On rate limited | триггер | Сервер отбросил сообщение из-за лимита частоты (60 сообщений в секунду на соединение). Отправляй реже |
| `ErrorCode` | число | Код последней ошибки |
| `ErrorMsg` | строка | Текст последней ошибки от сервера (по-английски) |

Серверные ошибки плагин пишет в `console` с префиксом `[StarkFlow]` и уровнем `error` — свойство
`Log level` их не скрывает (на `off` замолкает всё). Диалогов браузера (`alert`/`confirm`/`prompt`) плагин
не открывает никогда: `On error` — просто событие, выводи его игроку строкой в HUD или через `Browser: Log`.

| Код | Что значит | Что делать в игре |
|---|---|---|
| 100 | Не та версия протокола | Обнови аддон; переподключения не будет, они бессмысленны |
| 101 | Битое сообщение | Ошибка в игре или в плагине; смотри консоль |
| 102 | Ещё не поздоровался, `hello` не ушёл | Не отправляй `room.join` сразу после открытия сокета — жди `On connected` |
| 200 | Токен просрочен или не подходит к этому серверу | Плагин сам забыл токен и получит нового игрока: сохрани новый `AuthToken` |
| 300 | Комнаты нет | «Войти или создать» обрабатывает сам плагин и `On error` из-за пробного входа **не поднимает** (только строка в консоли); при обычном входе покажи «комната не найдена» |
| 301 | Комната заполнена | Предложи другую комнату из списка |
| 302 | Комната закрыта | Создать заново |
| 303 | Ты уже в комнате | Сначала `Leave room` |
| 305 | Ты не в комнате | Команда про стейт игрока или выход без входа |
| 306 | Некорректное имя комнаты | Пустое или длиннее 32 символов |
| 307 | Неверный пароль комнаты | Спроси пароль заново: комната закрыта (`RoomLockedAt`) |
| 308 | Комната с таким именем уже есть | Ответ на `Create room`: имя занято. Предложи другой код или `Join room` с этим именем. Старый сервер (без `welcome.unique`) эту ошибку не пришлёт |
| 400 | Ключ не разрешён | Ключа нет в схеме комнаты (режим strict) или плохое имя: только латиница, цифры, `_` и `.`, до 64 символов |
| 401 | Не тот тип значения | У ключа уже другой тип (число ↔ строка), либо значение не число/строка/bool |
| 402 | Действие запрещено | Ключ только для чтения (const/once/server) или принимает только `add` |
| 403 | Слишком большое изменение | У ключа есть `maxDelta`, прибавка превысила его |
| 404 | Выход за пределы | Значение вне `min`/`max` при `reject`, строка длиннее лимита, слишком много ключей или стейт комнаты переполнен |
| 500 | Слишком часто | Больше 60 сообщений в секунду на соединение |
| 501 | Слишком большое сообщение | Кадр больше 16 КБ |
| 502 | Сервер занят | Повтори позже |

## Что читать в каком триггере

| Триггер | Читай |
|---|---|
| On connected | `MyUserId`, `AuthToken`, `StatusString`; здесь можно `Join or create room` |
| On reconnecting / On disconnected | `StatusString` — показать «переподключаюсь…» |
| On joined room | `RoomId`, `RoomName`, `MyId`, `HostId`, `Resumed`, `RoomCreated`, `RoomPlayerCount`/`RoomMaxPlayers`/`RoomFree` (заполненность) |
| On created room | `RoomId`, `RoomName`, `MyId`, `RoomPlayerCount`/`RoomMaxPlayers`/`RoomFree` — разошли код друзьям |
| On room list received | `RoomCount` и в цикле по `loopindex`: `RoomNameAt`, `RoomIdAt`, `RoomPlayersAt`, `RoomMaxAt` |
| On player joined / left / connection lost / resumed | `LastPlayerId` + `LastPlayerName` (или `PlayerName(LastPlayerId)`) |
| On player prop (key) changed | `LastPlayerId` + ключ из условия → `PlayerProp(LastPlayerId, key)` |
| On host changed | `HostId`, `Is host` |
| On event (code) | `EventData`, `EventFrom` |
| On state (key) changed | `State(key)`, `ChangedValue`, `ChangedOld`, `ChangedBy` |
| On error | `ErrorCode`, `ErrorMsg` (для `Join room` и `Create room` — те же коды в своих триггерах) |

## Ники игроков

Свой ник читается всегда, даже до входа в комнату:

```
StarkFlow: On start of layout → Set player name to NameInput.Text & "!"
StarkFlow: On connected      → Browser: Log "я " & StarkFlow.MyName       // то, что задали
StarkFlow: On joined room    → Text Me: Set text to StarkFlow.MyName      // имя, подтверждённое сервером
```

Чужой ник — по id внутри триггера или по индексу в списке игроков:

```
StarkFlow: On player joined
    → Text Join: Set text to StarkFlow.PlayerName(StarkFlow.LastPlayerId) & " зашёл"
StarkFlow: On player left
    → Text Join: Set text to StarkFlow.LastPlayerName & " вышел"

StarkFlow: On other player's object created (tag "player")
    → NameTag: Set text to StarkFlow.PlayerName(StarkFlow.ProxyPlayerId)
```

```
StarkFlow: For each player
    → Text Row: Set text to StarkFlow.PlayerName(StarkFlow.CurrentPlayerId)

Repeat StarkFlow.PlayerCount times:
    → Text Row: Set text to StarkFlow.PlayerNameAt(loopindex) & " (" & StarkFlow.PlayerIdAt(loopindex) & ")"
```

Ник фиксируется сервером при входе в комнату (`Set player name` до `Join`/`Connect`) и уходит остальным
вместе с `player.joined`; в `player.left` сервер тоже присылает имя, поэтому `LastPlayerName` не пустой
даже у игрока, которого мы не успели увидеть. Имя из `room.joined`/`player.*` читается и после ухода
игрока из списка. Поменять ник на лету нельзя — отключись и подключись заново. Постоянный id устройства —
`MyUserId`, в комнате — `MyId`.

## Перебор игроков

```
Repeat StarkFlow.PlayerCount times:
    Set text PlayerRow: StarkFlow.PlayerName(StarkFlow.PlayerIdAt(loopindex))
```

`PlayerIdAt` читается внутри цикла — это важно, если игроков много.

## Значения и типы

- Логическое приходит как 1/0, отсутствующее — как 0. Сравнивай через `= 1`, а не через `= true`.
- `EventData` всегда строка. Числа и координаты собирай как `str(x) & "," & str(y)`, разбирай через
  `tokenat(EventData, 0, ",")`.
- `Set player prop` и `Set state` принимают число, строку или bool.
- Выражения читают **последнее** событие: если значение нужно позже, сохрани его в переменную.
